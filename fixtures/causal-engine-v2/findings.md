# 重做：把根因挖掘搬到「五种压力形态」层——结论是这个 join 目前物理上做不成，且形态层本身是「活动量」的二次编码

## 一句话结论（先说最诚实的那句）

在**产品真正在用的形态层（五种压力 pattern）**上重做挖掘后，昨晚「根因藏在耗竭、掏空才报警」的结论**无法升级到形态层**——不是被推翻，是**测不了**。原因是结构性的：能给出形态分类的穿戴数据**只覆盖 3/18–5/19 加一个孤立的 6/22**，而产生反刍信号的会议语料**从 5/24 才开始**。两段时间**零重叠**，跨源复现规则（会议 AND 原话同窗）在形态层上需要 0/26 天满足——**物理上无解**。更深一层：形态层在日粒度上其实是**活动量的二次编码**，不是自主神经状态——所以「耗竭形态承载根因」这个假设，在当前数据上是**一个没有生物指标支撑的断言**。

CEO 指出：四象限（心流 / 过载 / 恢复 / 耗竭）来自**旧的阴阳 avatar 版本**，是 pivot 前的遗留层，产品早已不用。真正在用、也是本报告的主轴，是**五种压力形态（stress pattern）**。

## 一、"balanced" 到底存不存在于形态层？——**不存在。**（附 file:line 证据）

CEO 要求核实是否有第六个「平衡」态。**代码与数据双向核实，结论是没有：**

- `Models.swift:136` — `enum LSPattern { case wood, fire, earth, metal, water }`，**正好 5 个 case，无 balanced**。
- `Models.swift:256-260` — `dominantPattern` 永远返回 5 个之一；当**所有分数为 0** 时**默认回落到 `.fire`（OVERDRIVE）**——所以 UI **永远无法显示「平衡」**，会把一个全平的日子误标成 OVERDRIVE。
- 后端 `wuxing.py:193-263` `infer_states` 只返回 5 个 element；激活阈值 = 50。「平衡」只是「没有任何 element 激活」的**缺省状态**，不是一个有名字的态。
- `api_server.py:1699` `ELEMENT_LABELS` — 只有 5 个。
- 代码里所有 "balanced" 字样都属于**别的层**：(a) 阴阳象限的 `in_flow`（旧名 balanced，迁移见 `schema.py:370`）；(b) Time-on-Balance 计时器指标 `is_currently_balanced`；(c) mock LLM 的 `category:"balanced"`（阴阳，映射到 in_flow）。**都不是形态层。**

**这更正了昨晚的文档**——昨晚把 "BALANCED" 列为第六个形态层状态是错的，它引用的其实是象限层的 in_flow。**数据侧印证：** 26 个佩戴日里，只有 1 天（3/28）没有任何 element 越过阈值，而那天在象限上是 in_flow、raw fire=46——**UI 仍会把它显示成 OVERDRIVE**。

## 二、最重要的形态学发现：五种压力形态在日粒度上是「活动量」的二次编码，不是自主神经状态

![原始 vs 门控形态](../assets/biometrics-2026-07/03_raw_vs_gated_pattern.png)

**读图：** 左轴是「原始生物信号算出的主导形态」（pre-gate），右轴是「App 实际显示的形态」（post-gate，经阴阳 eligibility 门控）。两者几乎不是同一回事。原始主导：TENSION 13 天、OVERDRIVE 9、STAGNATION 3、CONSTRICTION 1、**DEPLETION 0**。App 实际显示：**DEPLETION 19**、OVERDRIVE 7、其余全 0。机制是 `_enforce_element_eligibility` 在任何 recharging/running_on_empty 日强制把 `water=75`（DEPLETION），在 pushing_it 日强制 `fire=75`（OVERDRIVE），并把 wood/earth/metal 清零。而象限由**每日步数**驱动（Tudor-Locke 阳性判据），手表只戴半天 → 步数被大幅低估（佩戴日步数中位数 4,970 → 阳分<50）→ 结构性偏向 DEPLETION。**换句话说：App 显示的 DEPLETION 100% 是门控制造出来的，原始信号里 DEPLETION 一天都没出现过。这直接掏空了昨晚「根因在耗竭/DEPLETION」的落点。**

![每形态生理](../assets/biometrics-2026-07/08_per_pattern_physiology.png)

**读图（判别器图）：** 原始信号里两个样本最多的形态——TENSION（n13）与 OVERDRIVE（n9）——在**全天平均 HR** 上几乎完美分离（77.7 vs 103.3 bpm，Hedges g = **−3.26**，CI [−5.77, −2.36]），在 tonic 底线 HR 上也分（p10 67.2 vs 80.7，g = −1.65）。但在两个**金标准自主神经指标**上**分不开**：HRV（55.4 vs 62.2 ms，g = −0.42，**CI [−1.28, 0.67] 跨 0**）、静息 HR（63.8 vs 65.0，g = −0.27，跨 0）。

![HRV×RHR 状态空间](../assets/biometrics-2026-07/13_hrv_rhr_state_space.png)

**读图：** 把每个佩戴日画在 HRV × 静息 HR 平面上、按原始形态上色——**颜色完全混在一起**。自主神经标记无法区分形态。合起来的结论：**OVERDRIVE ≈「体力上忙碌的一天」，TENSION ≈「心血管正常、但 HRV 相对个人基线掉了一点的一天」**。形态层是活动量的下游产物——门控一层（步数），原始拆分又一层（HR 水平），共两层。

![PatternJoin 可行性](../assets/biometrics-2026-07/14_patternjoin_feasibility.png)

## 四、长期生物形态学深挖（越详细越好）

### 4.1 基线与漂移

![基线漂移](../assets/biometrics-2026-07/06_baseline_drift.png)

**读图：** HRV/RHR/tonic-HR 的 7/14/28 天滚动基线 + 变点 + regime 带 + 空窗。HRV 在佩戴窗内**方向性下行**：OLS 斜率 −0.50 ms/佩戴日，净 −12.4 ms，但 r²=0.06（弱）。regime 均值：**R1 三月下旬 68.8 → R2 四月 54.4 → R3 五月 53.1 ms**——一条真实的副交感储备下降梯度，代价是活动量上升（步数中位数 3,286 → 4,970 → 8,745，步数 OLS r²=0.14，最强趋势）。**变点检测（二段分割 + 5000 次置换 p）：全部不显著。** HRV 分割 5/9（p=0.35）；RHR 分割 5/9（d=1.02，p=0.15，最接近可注意）；n=26 下不存在稳健 regime 边界，「regime」是描述性带，不是检测到的变点。**中六月无可主张的 regime**——空窗无数据，6/22 的 RHR/HR 落在个人均值（不是「低」）。

### 4.2 节律

![昼夜节律](../assets/biometrics-2026-07/09_circadian_profile.png)

**读图：** 干净的日间 HR 形态——早晨上升、午间平台 ~75–90、傍晚运动峰 ~18–20 时（中位可达 110），HRV 镜像倒置。**但这被佩戴时间污染**：手表基本只在 8:00–22:00（太平洋时）佩戴，23:00–07:00 近零样本，18–20 时有巨大样本尖峰。**不存在真正的睡眠/夜间自主神经数据。**

- **周内结构（chart 10）：** 仅方向性，每工作日 ~1–6 个佩戴日。表面上的周六 tonic-HR 高（85.5）是单日伪影（3/28 运动周六）。无可存活的工作日主张。
- **工作-会话耦合（chart 12）：** **检测不到耦合。** 每个会议↔生物指标 Spearman CI 都跨零——会议~步数 ρ=0.19、会议~HR ρ=0.22、会议~HRV ρ=−0.04。此 n 下日历会议密度不预测任何生物指标。

## 六、Stress Pattern 2.0 — 用**实测**生理签名重写（替换昨晚的假设表）

设计不变：**保留 TENSION/OVERDRIVE/STAGNATION/CONSTRICTION/DEPLETION 五态**（对外不提五行；**确认没有第六个 balanced 态**，见第一节；建议给 UI 加一条显式的「基线内/无激活」显示，替掉现在误落到 OVERDRIVE 的 bug）。变的是签名从「假设」换成本轮**26 佩戴日实测**：

| Pattern | 实测判别力（本轮真数据） | Watch 现在能做的签名 | Oura 接入后增强 |
| --- | --- | --- | --- |
| **OVERDRIVE 过载** | **强、可测**：全天 HR 103.3、tonic p10 80.7、HRmax 常破 160（运动日）。是本轮最干净的形态 | 工作时段持续高 HR + 高活动量。**注意：当前它主要在编码「体力忙碌」而非唤醒** | + 白天压力时段占比、恢复窗缺失——把「忙」和「过度唤醒」分开 |
| **TENSION 紧绷** | **中、可测但与 OVERDRIVE 仅靠 HR 水平分**：HR 77.7、HRV 55.4（较个人基线偏低），自主神经指标与 OVERDRIVE 不显著可分 | 正常 HR + HRV 相对个人 14 天基线下探、无高活动量 | + 夜间 rMSSD 压低、呼吸率上浮——**这才是把 TENSION 从「活动量」里救出来的关键** |
| **STAGNATION 停滞** | **弱、n=3 但方向干净**：步数中位 848（清晰低活动尾）、HRV 反而高 74.1 | 低活动量 + HRV 方差收窄 + 低阳分 | + 睡眠时相漂移、白天 engaged 段稀少 |
| **CONSTRICTION 收缩** | **不可测**：n=1 轶事，全程仅 3 条呼吸样本、无定位/社交数据 | 现结构无法可靠定义——需事件级呼吸+定位 | + 事件时段呼吸率尖峰、SpO2 正常（排除生理原因） |
| **DEPLETION 枯竭** | **原始信号 0 天——当前 100% 由步数门控制造**：门控 DEPLETION 就是「低步数日」，HRV 与 OVERDRIVE 无差 | **当前定义不可信。** 必须停止用「阴阳象限 + 步数」代理 DEPLETION | + Readiness（睡眠债+体温偏差+恢复指数）——**Oura 最强的一块，也是唯一能给 DEPLETION 真定义的数据** |

三条设计原则（不变，但现在有数据背书）：①每条指标带**个人 14 天基线对比**，不用绝对阈值——本轮已证明绝对量（步数）会把形态劫持成活动量；②指标缺失就降级显示「无穿戴明细」，**永不编数**（本轮 6 月候选全无生物支撑，就该如实留白）；③对外只出 pattern 名 + 人话证据行，可展开依据。

**Watch → Oura 的诚实差距（本轮量化后更硬）：** Watch 现状只能给出 OVERDRIVE（靠活动量）的粗签名，TENSION 会与之混淆，**DEPLETION 完全给不出真签名**（原始信号里根本不出现）。Oura 补的夜间层（整夜 rMSSD、体温偏差、睡眠债、恢复指数）正是 DEPLETION 与 TENSION 唯一的出路。**产品含义：Oura 接入的第一优先级，就是把 DEPLETION 从「步数门控伪影」升级为「夜间恢复账本」——否则 DEPLETION 这个形态在数据上就是空的。**

## 七、下一步（按优先级，已按本轮结论修正）

1. **修 HealthKit 同步**——这是**前置阻塞**，不是第 2 优先。佩戴窗必须与 June 式反刍语料重叠，否则形态 join 永远无解（本轮的核心教训）。
2. 修 `dominantPattern` 全 0 回落到 OVERDRIVE 的 bug（`Models.swift:256-260`），加显式「基线内」显示。
3. **停止用「阴阳象限 + 步数」代理 DEPLETION**；把门控 `_enforce_element_eligibility` 的步数依赖标为已知偏差。
4. Oura 真数据流评估，落 DEPLETION/TENSION 夜间签名。
5. 验证协议不变：任何候选处理后只进「已处理，未验证」。

## 八、限制（说给未来的自己）

- 形态层实测只有 26 个佩戴日、全在 3/18–5/19 + 孤点 6/22；HRV 共 77 条（~2/天）→ 所有 HRV 效应仅方向性。
